# Production Go
## Порядок работы
1. Прочитай go.mod, существующие соглашения, тесты и публичный контракт.
2. Выдели минимальное изменение и перечисли допущения.
3. Используй стандартную библиотеку, пока нет причины добавлять зависимость.
4. Передавай зависимости конструкторами; определяй интерфейсы у потребителя.
5. Оборачивай ошибки через fmt.Errorf с %w, сравнивай через errors.Is/As.
6. Не меняй API, формат хранения и конфигурацию молча.
## Проверка
- gofmt для измененных Go-файлов.
- go vet ./... и go test ./... в соответствующем модуле.
- При изменении конкурентного кода: go test -race ./....
- Укажи неподтвержденные проверки и компромиссы.
## Антипаттерны
Глобальные изменяемые зависимости, бессмысленные интерфейсы, пакет utils для всего, игнорирование ошибок, бесконечные фоновые задачи.
## Итог
Покажи изменения, тесты, риски совместимости и ограничения.
